Reading the ledger: the columns run front-end to back-end exactly as the request travels — the software each step crosses, the hardware it rides, and the checks that watch both. The checks column is the platform’s work order: availability answers is it up, quality answers is it good, and L3 assertions answer did the money move correctly — the layer where a 200 OK can still be a failed payment. All three objectives sit in one table: a full-flow health check across software and hardware; quality defined per segment, which Section 02 turns into bands; and a root cause locatable when behaviour turns abnormal, which Section 03 reads as a fingerprint. Every check here is read-only — probes from outside, log and receipt reads, canary queries on read replicas, file checks. Beside your stack, never in the transaction path.
A check is only half a sentence. "Gateway p95 is 480 ms" means nothing until you know the band it should live in. Section 02 gives every segment its numbers — the floor for availability, the band for quality, and the line where someone gets paged.

Reading the bands: these are calibration outputs of the first two observation weeks per bank, not promises — the floor is what the segment must clear to count as up, the band is what it looks like when nobody notices, and the page line is where a human is woken. Quality, in one sentence, is the band the customer never notices. Section 03 is what the same checks say when something is wrong.
Normal is the baseline; the payoff is abnormal. When behaviour turns strange, the same checks read top-to-bottom become a fingerprint — and the fingerprint, not a war-room, names the layer and the team.
