How to read this register

what each column is, and what it is not

Codes, not HTTP statuses

—

Count is the seeded week's occurrences of that result code, and share is its portion of the whole register — both published by errorTracking(). The page sorts and filters them; it never recomputes one. There are no range chips on this screen: the register is the week (Aug 23 00:00 – Aug 29 23:55), and a code with a shorter window would not be the same row.

SLA %, ETA and the workflow state

SLA % is the owning service's response-time compliance for the week (its share of requests inside T_ms). It is a property of the service, not of the code, so several codes on one service read alike. Core Adapter has no ingress route of its own — it is measured from egress edges, where response-time compliance cannot be derived — so its cells read NO DATA rather than 0 %.

ETA is a timeline index into the same week, printed as <month> <day> HH:MM; an ETA past Aug 29 23:55 reads Aug 30 and is still open. Status is workflow, not health: changing it stores a local override in this browser only (localStorage key pulse_tracking_v1, written inside try/catch) and leaves every number untouched.
